# 聊天前端(Claude API + 语音)

打字发送,Claude 用文字回复,同时用 TTS 把回复念出来。是聊天窗口模式(发一句、回一句)。语音输入暂时下线了(之前的浏览器语音识别不够稳定),之后如果要做"电话"式的实时语音对话会另外重新设计。

底部是四个页签:**主页**(每日一句英文 + 每日推荐歌曲 + 今日温度)、**聊天**(原来的对话窗口)、**日记**(苏晏自己写的日记,可以回复)、**更多**(设置)。

TTS 默认用浏览器自带的 `speechSynthesis`;配好 ElevenLabs 或 MiniMax 的环境变量后会自动切换成克隆音色朗读,不用改代码(两个都配了优先用 ElevenLabs)。每条 AI 回复气泡旁边有个 ▶ 按钮,可以重新播放。

## 本地运行

```bash
cd voice-chat
npm install
cp .env.example .env   # 填入你的 ANTHROPIC_API_KEY
npm start
```

打开 http://localhost:3000。

走中转站(而不是官方 Anthropic 账号)的话,把中转站给的接口地址填进 `.env` 的 `ANTHROPIC_BASE_URL`(形如 `https://xxx.xxx/v1`,注意不要带 `/v1`,SDK 自己会加,详见"已知限制"里的坑),`MODEL` 按中转站文档里给的模型名填(有些中转站的 model 名字带方括号前缀,是真正字符串的一部分,不是装饰,要原样复制)。

## 使用说明

- 打字 + 回车/点"发送"。
- AI 回复默认只显示文字,**不会自动念出来**——想听语音自己点气泡旁边的 ▶ 按钮,点了才会去合成语音(懒加载),不会一打开对话就疯狂跑 TTS 账单。
- 聊天页左上角 ☰ 是对话列表,可以新建/切换/改名/删除多个独立对话,每个对话的记录都存在 Supabase 里,换设备登录也能接着聊。
- 没配置 Supabase 时,顶部会有提示,输入框也会被禁用——聊天记录持久化是必须有数据库的,见下面"接入 Supabase"。
- 输入框左边的叶子图标可以发图片,一次能多选(最多 6 张),选好会出一排小预览,每张右上角有 ✕ 能单独移除,确认没问题再发送;模型要支持多模态(能看图)才认得,`MODEL` 换成不支持的会报错。图片存在 Supabase Storage 里,历史记录里也能看到;为了控制成本,只有"当下这一轮"会把图片真的发给模型,之后的对话不会每次重发。
- 自己发的消息气泡右边有个 ✎,点一下能改文字。**改完点"保存"会把这条消息之后的所有记录(她后面发的、AI 回的)都删掉**,相当于"从这条改过的消息重新开始",然后会自动让 AI 针对新内容重新回一条——不是单纯改个错别字这么"安全"了,是真的会回溯掉后面的对话,慎用。

### 主页

- 每次打开随机换一句英文句子(下面配一句中文翻译),右上角 ⟳ 可以手动换一句(纯前端内置的一份句子清单,不消耗 API)。
- 每天一首推荐歌曲,只推荐(歌名/歌手/一句推荐理由),不播放实际音频、不碰账号信息。歌曲卡片下面有个"去网易云听"链接:服务器会拿歌名+歌手去网易云自己的公开搜索页匹配一下(不需要登录,只读,匹配不到也不会报错),匹配上了就直接链到那首歌的页面——网易云 App 如果装了,点开会直接跳进 App 播放那首歌,不用自己再搜一遍;没匹配上就退回成一个搜索链接。这个匹配用的是网易云没有正式开放的一个老接口,不保证 100% 找得到、也不保证永远不失效,失效了顶多就是退回搜索链接,不会导致主页坏掉。不想要今天这首,点卡片右上角 ⟳ 换一首,同一天不会重复推荐已经划走的。
  - 两类"推荐不准"的问题都修过一版:①模型偶尔会编一首听起来像真的、实际不存在或者歌手记错的歌——已经在提示词里加了"只能选你非常确定真实存在、原唱信息确定无误的歌"这类约束,降低瞎编概率,但没法保证 100% 不发生(毕竟是模型生成的),遇到明显不存在的歌可以直接换一首。②之前网易云搜索匹配是直接拿搜索结果第一条,没有校验歌名和歌手是不是真的对得上,导致点进去链接是"标题像但唱的人不对"的歌——已经改成会检查候选结果的歌名和歌手是不是都对得上,对不上就不采用、退回成搜索链接,不会再乱链一个错的歌手。
- 如果今天已经写了日记,还会显示"今日温度"。

### 日记

- 不是一天一篇的固定日记,是"想到就写":每次聊完天,有 20% 的概率她会顺手也写一篇日记记下这段对话的感受;打开日记页也会顺便判断一下要不要写一篇。两种情况都有一个一小时的间隔保护(`MIN_DIARY_GAP_MS`),避免聊得频繁的时候日记刷屏。
- 日记页标题右边有个 ✎,点一下可以立刻让她现在就写一篇,不受一小时间隔限制。
- 内容是根据"上一篇日记之后"的聊天记录写的,如果那段时间根本没聊天,她也会写,只是会变成单纯写点自己此刻的心情、突然想到的念头,不会硬凑聊天内容。
- 更多页里的"自动写日记"开关关掉之后,聊天/开日记页都不会再自动触发,只有手动点 ✎ 还能用。
- 可以在日记下面回复,回复会立刻显示,苏晏在后台"看到"之后会自己写一段回信,页面会自动轮询几次把回信补上,不用手动刷新。
- 每篇日记头上是天气 + 心情 emoji(如果配了"所在城市"的话),不再显示那个 0-100 的温度数字了——数字放在心情 emoji 旁边看着太挤,已经拿掉,温度还在存,只是不在日记这里露出来。
- 日记和推荐歌曲原来是让模型直接输出 JSON,但日记正文经常带引号对话,模型偶尔会漏转义引号导致 JSON 解析失败,整段原始 JSON 文本就会直接显示出来(不是内容错了,是解析失败的兜底显示)。已经改成不用 JSON 的简单文本格式,不会再有这个问题。

### 主页天气 / 更多页所在城市

- 更多页可以填一个"所在城市"(比如"上海"),天气用的是 Open-Meteo(免费、不用注册 key)。填好之后主页标题下面会出现一个天气小标签,日记头上也会带上当时的天气。不填就都不显示,不会报错。

### 更多(设置)

- System Prompt / 身份设定、导入背景资料、浏览器朗读语言音色,和原来一样。
- 新增:"相识于"日期(自动算在一起多少天)、自动写日记 / 日记里显示心情温度 / 每日推荐歌曲 / 起床入睡状态提示 四个开关,存在 `settings` 表里,全设备共用。

## 接入 Supabase(聊天记录持久化 + 多会话 + 记忆压缩)

1. 去 [supabase.com](https://supabase.com) 用 GitHub 账号注册,新建一个项目(免费额度够用)。
2. 项目建好后,进 **SQL Editor**,把仓库里 `supabase-schema.sql` 的内容整段粘贴进去执行一次,会建好 `sessions` / `messages` / `memories` / `settings` / `diary_entries` / `daily_songs` 几张表。**已经建过库的老项目**只要重新把整个 `supabase-schema.sql` 再粘贴执行一次就行——里面全是 `create table if not exists` / `add column if not exists`,已存在的表和字段会跳过,不会重复建、也不会清空已有数据,新增的 `diary_entries` / `daily_songs` 表和 `settings` 表新增的几个字段会被补上。
3. 项目设置里的 **Settings → API** 页面,拿到 **Project URL** 和 **`service_role` 或 `anon` key**(个人项目用哪个都行,填进 `.env` 的 `SUPABASE_URL` / `SUPABASE_KEY`)。
4. 重启服务,顶部的"未配置 Supabase"提示应该消失,输入框可以用了。

**记忆压缩**是怎么回事:每次对话后,后端会检查当前会话"可见消息"的总字数,超过 `COMPRESS_CHAR_THRESHOLD`(默认 14000 字)就会把最早的一批消息(保留最近 `COMPRESS_KEEP_MESSAGES` 条,默认 20 条不动)丢给模型压缩成一份详细记忆存进 `memories` 表,原始消息标记为不可见(数据还在,只是不再拼进上下文)。这样对话越聊越长也不会无限增加 token 成本。默认用主模型自己做压缩;配置 `DEEPSEEK_API_KEY` 之后会改用更便宜的 DeepSeek 做这件事,不影响主对话质量。

阈值调得比较宽松是故意的——压缩本质是有损的,压得太勤、摘要写得太短,具体细节会被压没,问起来就会"打哑谜"、前言不搭后语。如果还是觉得它"聊着聊着变笨",可以把 `COMPRESS_CHAR_THRESHOLD` 调得更大,甚至先关掉观察(设一个很大的数字,比如 999999)。

压缩出来的"记忆"存进 `memories` 表后不会只有一条——聊得越久、触发压缩的次数越多,`memories` 表里的行就越多,而这些行**每次对话都会全部拼进提示词里**,不加处理的话,记忆本身也会变成一个跟着对话一起越滚越大的东西,不是真正意义上"占用量固定"的记忆库。所以加了第二层:这些记忆摘要累计超过 `MEMORY_CONSOLIDATE_THRESHOLD`(默认 6000 字)时,会自动把已有的所有记忆再合并压缩成一条,把"记忆"这部分的体积摁住,不会无限膨胀。

如果某个对话聊得特别久,你发现它突然像是"完全不记得之前聊过什么",很可能是压缩(或者记忆合并)那一步因为中转站不稳定而失败了几次,历史记录/记忆没能被及时收拢,原始上下文堆得太大导致模型注意力跟不过来——不是真的丢数据。去 Render 的 Logs 里搜 `compressIfNeeded` 或 `consolidateMemoriesIfNeeded` 能看到是不是这个原因(有没有连续报错、成功了没有)。

**发图片**需要额外建一个 Storage 桶:服务器启动时会自动尝试创建一个叫 `chat-images` 的公开桶,一般不用手动管;如果启动日志报 `createBucket error`,就去 Supabase 的 **Storage** 页面手动建一个名字为 `chat-images` 的 **Public** 桶。另外 `messages` 表需要 `image_url` / `image_urls` 两个字段(后者是数组,存"一次发多张"的情况),老项目在 SQL Editor 里跑一下这两行就行(新项目跑完整个 `supabase-schema.sql` 已经包含):
```sql
alter table messages add column if not exists image_url text;
alter table messages add column if not exists image_urls jsonb;
```

## 接入 ElevenLabs 克隆音色

1. 去 [elevenlabs.io](https://elevenlabs.io) 注册登录。
2. 左侧菜单"音色"里点 + 号,上传一段你的干净音源做声音克隆(不需要本地脚本,网页里直接传就行)。
3. 克隆好之后进这个音色的详情页,把它的 **Voice ID** 复制出来(一串字母数字,不是名字)。
4. 右上角头像菜单 → **工作区设置** → **API Keys**,创建/复制一个 key。
5. 填进 `.env`:`ELEVENLABS_API_KEY`、`ELEVENLABS_VOICE_ID`。
6. 重启服务(或者线上改完 Render 环境变量重新部署),前端会自动切换成 ElevenLabs 朗读。

`ELEVENLABS_MODEL` 默认 `eleven_v3`——**必须是 v3**,只有这个版本认识 `[breathing heavily]` `[whispers]` `[laughs]` 这类方括号表演标签,换成 v2 系列这些标签基本没用。免费账户每月有字符额度限制,超了要么等下个月刷新要么升级订阅。

ElevenLabs 是直连官方接口,不走中转站,所以不会有中转站那种断线/不稳定的问题——这里说的只是"点 ▶ 按需合成一段语音"这种一次性请求,不是实时语音通话,稳定性和之前的 MiniMax 是同一个级别。

**怎么调出"活人感"而不是播音腔**:

- `ELEVENLABS_STABILITY`(默认 0.3):越低声音起伏越大、越有表演感;调到 0.5 以上会明显变平、变机械。
- `ELEVENLABS_STYLE`(默认 0.88):越高越有戏、越夸张。
- `ELEVENLABS_SPEED`(默认 1.08):略快于正常语速(1.0),更像日常说话而不是念稿。
- 回复文字里的 `(笑着)` `(小声)` `(喘气)` 这类中文动作描写,朗读时会自动翻译成 ElevenLabs 认识的英文表演标签(比如 `[laughs]` `[whispers]` `[breathing heavily]`),不再是直接被删掉——这样动作描写能真正影响声音的表演,不只是聊天气泡里的装饰文字。能识别的动作词是个小词典,覆盖笑/叹气/小声/喘/哭/生气/兴奋这几类,认不出来的还是照常从朗读文本里去掉。
- 这套标签本质是"表演提示",不是每次都 100% 稳定生效,同一句话不同版本效果可能不一样,属于正常现象。
- 参数改完存到 Render 的环境变量里重新部署就行,不用改代码。

## 接入 MiniMax speech-02 克隆音色

1. 去 [platform.minimax.io](https://platform.minimax.io)(国际版)或 [platform.minimaxi.com](https://platform.minimaxi.com)(国内版)注册,拿到 `API Key` 和 `Group ID`,填进 `.env` 的 `MINIMAX_API_KEY` / `MINIMAX_GROUP_ID`。国内版记得把 `MINIMAX_API_HOST` 改成 `https://api.minimaxi.com`。
2. 准备一段 10 秒~5 分钟、mp3/m4a/wav、不超过 20MB 的干净音源(没有背景噪音,不然大概率克隆失败或跑出杂音,得重新花钱录)。
3. 克隆有两种方式:
   - **有本地开发环境**:跑脚本一行命令搞定
     ```bash
     node scripts/clone-voice.js ./你的音频.mp3 suyan-voice-01
     ```
   - **只有手机/没装 Node**:部署上线后,打开 `https://你的域名/clone.html`,上传音频、填音色 ID,点按钮,网页会调用部署好的服务器完成上传+克隆(服务器有完整外网权限,不受本地网络限制)。这个页面会消耗 MiniMax 余额,建议配一个 `CLONE_PASSCODE` 环境变量做访问口令,不然任何知道网址的人都能用你的余额瞎克隆。
   
   成功都会提示把 `MINIMAX_VOICE_ID=suyan-voice-01` 加到环境变量。
4. **新克隆的音色 7 天内没有被真正合成过一次会被自动清理**,克隆完记得马上开一次通话说句话用一下。
5. 重启 `npm start`,前端会自动检测到配置,把朗读换成 MiniMax。想切回浏览器朗读,把 `.env` 里的 `MINIMAX_*` 清空即可。

`MINIMAX_MODEL` 默认 `speech-02-turbo`(低延迟,适合实时通话);想要更好的音质、能接受更慢一点可以改成 `speech-02-hd`。

## 已知限制

- ElevenLabs 和 MiniMax 都没配时用的是浏览器原生 `speechSynthesis`,音色取决于操作系统自带的语音包,不是高保真人声;配好任意一个之后走克隆音色,见上面两节。
- iOS Safari 对"没有直接用户点击就自动播放音频"管得很严,已经做了播放解锁处理,但如果换了浏览器/系统还是遇到听不到声音,先看是不是需要手动点 ▶ 按钮。
- 中转站接口地址(`ANTHROPIC_BASE_URL`)不要带 `/v1` 后缀,SDK 会自动拼接,带了会变成 `/v1/v1/messages` 导致 404。

## 部署

这是个普通的 Node/Express 应用,`ANTHROPIC_API_KEY` 只存在服务端,不会下发到前端。选一个支持长连接/流式响应、外加 HTTPS 的平台即可,比如:

- **Render / Railway / Fly.io**:直接连 GitHub repo,设置根目录为 `voice-chat`,构建命令 `npm install`,启动命令 `npm start`,配置环境变量 `ANTHROPIC_API_KEY`。
- **自己的服务器**:`npm install && npm start`(建议用 pm2 常驻),前面挂 nginx 做 HTTPS 反代。
- Vercel 的 Serverless Functions 对长时间 SSE 流支持有限,不太推荐;真要用 Vercel 建议改成 Edge Function 或直接用上面几个平台。

部署完把域名换成你的服务地址访问即可,不需要改代码。
